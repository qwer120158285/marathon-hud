# 格位网格与布局存储

组件定位必须可跨横竖预设复用，且不允许出现小数像素坐标。决定用固定格边长的整数格位网格表达布局：网格线铺满整张画布，安全区作为独立的硬约束叠加其上；跨预设采用 A 方案，且同一份候选布局必须对所有目标预设联合校验通过才能成为正式布局。

## 规格

- 基准格边长 40 px @ 短边 1080；自定义分辨率按 `min(W,H) / 1080` 等比缩放。
- 网格线铺满整张画布：抖音 1080×1920 → 27 列 × 48 行；B 站 1920×1080 → 48 列 × 27 行。
- 网格原点为画布左上角 `(0,0)`；安全边距不参与格位取整，安全区边界可以切过格位。
- 布局以「四角锚点 + 整数格位」存储：`anchor: top-left | top-right | bottom-left | bottom-right`，`col`、`row`、`colSpan`、`rowSpan` 均为整数，不存像素坐标。
- 每个组件另存 `zIndex`（绘制顺序）与 `visible`（是否参与渲染）；布局文件保存画布预设标识与 `gridVersion`，避免日后网格规则变化导致旧布局被错误解释。编辑预设与适用预设的拆分见 ADR 0005。

## 网格语义（Q16）

网格线范围与可放置格位范围是两个不同概念：

1. **网格线范围**：铺满整张画布（抖音 27×48、B 站 48×27），仅作视觉辅助，不代表所有格位都能放置组件。
2. **可放置格位范围**：只允许完整落在安全区内的整格。以抖音竖屏为例，左右安全边距 64 px、格边长 40 px，左右第一个完整可放置格位从 `col 2` 起；顶部 160 px、底部 240 px 同理按整格内缩。
3. 边界判断统一使用组件的**完整边界矩形**，而不是只判断起始格。

最终规则：**网格铺满画布，可放置区域受安全区硬约束**。ADR 0003 中「网格范围仅限安全区」按「可放置格位范围」解释，二者不冲突。

## 交互规则

跨格允许；Resize 按整数格；不提供像素微调；组件重叠允许，编辑器高亮提示冲突但不阻止导出。冲突检测区分「视觉重叠」（边界矩形相交）与「允许的层叠」（使用者显式设定 zIndex 的覆盖关系），不做强制互斥、不做自动避让。网格线默认显示、可关闭。

## 决策：跨预设采用 A 方案（Q15）

1. 组件的 `colSpan`、`rowSpan` 在不同画布预设之间保持不变。
2. 格边长按画布短边比例缩放，因此同一基准短边下组件物理尺寸一致。
3. 组件位置依据 `anchor + col + row` 映射。
4. 不因画布方向变化而自动改变组件尺寸。
5. B 方案（保持画布相对比例）仅作为原型对照开关，不进入正式布局配置，也不参与正式导出。

选择 A 而非 B 的理由：跑步 HUD 的文字与数据卡在不同画幅下保持可读的物理尺寸，比严格保持画布相对比例更重要。原型实测 B 方案在横屏会把路线图压成扁椭圆、数据卡拉宽压矮；A 方案两端尺寸一致。同一份布局跨横竖屏可用，不等于组件物理尺寸要随画幅比例变化——两种画布短边相同，40 px 格边长保持相同物理尺寸，变化的是可用列行数与锚点映射结果。

## 联合校验约束（Q15）

**任何布局变更，都必须对所有目标预设执行联合校验，全部通过才能保存或发布。**

| 校验项目 | 抖音竖屏 | B 站横屏 |
| --- | --- | --- |
| 组件是否越过安全区 | 必须通过 | 必须通过 |
| 格位是否有效 | 必须通过 | 必须通过 |
| 组件尺寸是否有效 | 必须通过 | 必须通过 |
| 锚点映射是否有效 | 必须通过 | 必须通过 |
| 层级及重叠提示 | 检查 | 检查 |

如果一个布局在竖屏通过、横屏越界，就不能作为正式布局保存。

工作流：

```
使用者修改布局
      │
      ▼
生成候选布局
      │
      ▼
抖音竖屏校验 ──▶ B 站横屏校验 ──▶ 其他启用的目标预设校验
      │
      ├── 任一失败 → 拒绝提交，展示具体错误
      ▼
   全部通过
      │
      ▼
保存正式布局
```

联合校验必须基于**同一份候选布局**与**同一版本的预设配置**，避免校验过程中预设发生变化，导致校验结果与最终保存结果不一致。

## 已知约束

A 方案下横屏安全区只有 880 px 高，按锚点贴边的上下组件容易挤到一起（原型初版出现 `route × metrics` 层叠，把数据卡从 10 格改为 8 格才消掉）。该情形由联合校验的重叠检查暴露并提示，不做自动避让。

## 备选方案

B 方案：保持组件在画布中的相对比例，横竖屏时组件尺寸随画布比例变化。未采用，理由见「决策」；仅在原型中保留为对照开关。
