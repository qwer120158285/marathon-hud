# 共享绘制模块 + 双端薄适配层

浏览器里的布局编辑器与命令行离线渲染器必须使用同一套绘制逻辑，否则两套实现会长期漂移、预览与成片不再对应。决定抽出一份只依赖标准 Canvas 2D 接口的共享绘制模块，浏览器与 Node 各自提供画布创建、字体注册等薄适配层。

## 技术边界

1. **共享绘制逻辑，不共享运行环境。** 核心模块不得直接引用 `window`、`document`、DOM 或 Node 专有 API；画布创建、字体注册、资源加载由两端适配层提供。
2. **字体必须统一。** 字体文件随项目打包，两端显式注册；必须等字体加载与注册完成后才开始绘制，避免字体回退造成文字尺寸与布局偏移。
3. **Golden Image 不要求逐像素相同。** 不同平台的 Canvas 实现、字体抗锯齿与底层图形库存在细微差异；采用像素差异阈值，并对布局、颜色、位置等关键区域设置更严格的校验。

## 备选方案

CLI 生成图片，编辑器只展示截图。

不选它的原因：编辑器拿不到真正的实时交互预览，调整参数后的反馈链路是割裂的；后续组件调试与布局编辑也难以支持。

## 代价

需要维护双端适配层、字体加载时序，以及视觉一致性测试。

## 验收标准

同一组输入数据，在浏览器与 Node 渲染出的视觉结果必须符合下列容差；布局、颜色、位置等关键区域适用更严格的阈值。

### 字体

- **Inter**，SIL Open Font License 1.1；字体文件随项目打包，不依赖操作系统字体。
- 浏览器与 Node 分别显式注册同一字体文件；固定字体文件版本及 SHA-256，防止日后升级字体导致基准图变化。
- 数字指标启用等宽数字（`tabular-nums`），避免 PACE / HR / CAD 数值跳动时宽度抖动。
- 字体加载与注册完成后才能开始 Golden Image 测试与正式渲染。

### Golden Image 容差

| 校验范围 | 允许差异像素比例 | 单通道最大偏差 |
| --- | --- | --- |
| 全图 | ≤ 1% | ≤ 8/255 |
| 关键区域 | ≤ 0.2% | ≤ 8/255 |

计算口径：

1. 一个像素只要 RGBA 任一通道的绝对偏差 > 8/255，就计为差异像素；**Alpha 通道也参与比较**。
2. 差异像素比例 = 差异像素数 / 当前校验区域总像素数。
3. 全图与关键区域分别计算，不能用全图结果掩盖局部问题。

关键区域由两部分组成：① 每个组件的边界矩形向外扩展 8 px；② 文字实际绘制包围盒及其基线附近的保护带。第二项以文字实际绘制包围盒为基础，而不是只取一条基线，否则会漏掉上升部、下降部与数字边缘。

### 测试矩阵

固定示意数据 × 两个目标预设（抖音竖屏 1080×1920、B 站横屏 1920×1080）各一张基准图；浏览器与 Node 各输出 PNG，与同一基准图比较「全图 + 关键区域」。两端必须使用同一份数据、同一份布局、同一套字体资源、同一组渲染参数；并固定 Canvas 尺寸、设备像素比为 1、颜色空间与透明背景处理方式，避免测试环境差异。

验收：浏览器 Canvas 2D 与 Node `@napi-rs/canvas` 分别与同一基准图比较，均通过上述阈值。

### 基准图维护

未来升级 `@napi-rs/canvas`、底层 Skia 或字体版本，必须重新审查基准图；不能为了让测试通过而随意放宽容差。

## 最终原则

浏览器原型就是最终渲染器的可视化预览，而不是另一套独立实现。
