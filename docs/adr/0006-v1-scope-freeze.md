# 首版范围冻结

先验证一条完整可工作的离线渲染链路，而不是一开始就把工具做成复杂的视频处理平台。首版只交付「编辑器出布局 → CLI 逐帧出 RGBA → FFmpeg 合成」这一条链路。

## 唯一交付链路

```
HTML + Canvas 编辑器（原生、无构建）
        │
        ▼
   project.json
        │
        ▼
 Node.js CLI（加载项目 → 解析运动数据 → 逐帧生成 RGBA）
        │
        ▼
 FFmpeg（原视频 + HUD RGBA → 合成 → H.264 MP4）
        │
        ▼
      成片
```

## 技术选型（冻结）

| 模块 | 技术 |
| --- | --- |
| 编辑器 | 原生 HTML + CSS + JavaScript |
| 编辑器绘图 | 浏览器 Canvas 2D |
| CLI | Node.js |
| CLI 绘图 | `@napi-rs/canvas` |
| 共享绘制 | 独立 JS 绘制模块 |
| 项目配置 | `project.json` |
| 视频合成 | FFmpeg |
| 数据输入 | TCX 优先，FIT / GPX 后续适配 |

编辑器不引入 React、Vue、Vite、Webpack 等框架或构建工具。零构建不等于编辑器可以直接访问本地任意文件：首版通过本地 HTTP 服务或明确的文件选择接口加载项目资源，规避浏览器 `file://` 安全限制。

## 时间轴同步仍为硬性要求

不做 PTS 精确校验，不代表完全不处理时间轴同步。首版仍必须保证：

- 固定 FPS；
- 视频与 HUD 使用同一输出时间轴；
- 帧数与视频时长正确对齐；
- 对齐偏移 `alignmentOffsetMs` 生效；
- 不允许因 Node 渲染速度不同而改变运动数据时间。

实现口径：第 n 帧的运动时刻为 `t = n / fps + alignmentOffsetMs`，据此从采样点插值取数，与实际渲染耗时（墙钟）无关。否则即使合成成功，配速与心率也可能与视频不同步。

## 首版验收标准

1. 编辑器可以加载并修改 `project.json`。
2. 支持网格布局、组件拖动、缩放与联合预设校验。
3. 浏览器与 Node 使用共享绘制模块。
4. CLI 能读取运动数据并逐帧生成完整 RGBA 流。
5. FFmpeg 能将 HUD 与原视频合成。
6. 输出 1080p 竖屏或 1080p 横屏 MP4，取决于目标预设。
7. Golden Image 两个预设均通过（ADR 0001）。
8. 至少完成一段真实视频的端到端渲染验证。

## 备选方案与代价

先做完整的视频处理平台（断点续跑、PTS 校验、编码器基准、实时预览）。不选原因：这些能力都依赖一条已经跑通的渲染链路，提前做会把首版反馈链路拉长。代价是首版对异常中断与编码性能没有内建观测，只能靠重跑与 FFmpeg 自带日志。
